# Flicky (Genesis) Disassembly

Disassembly of Flicky for Sega Genesis/Mega Drive. The source assembles with the AS Macro Assembler to produce a byte-accurate ROM.

This project is based on approaches from [alien_soldier_src](https://github.com/oranguthang/alien_soldier_src).

**AS Assembler**: http://john.ccac.rwth-aachen.de:8000/as/index.html

## Quick Start

```bash
git clone <repo>
cd flicky_src

# Place a legally obtained original ROM in the project root:
#   Flicky (UE) [!].bin   (SHA-1 83d8bbf0a9b38c42a0bf492d105cc3abe9644a96)

make init           # Validate the ROM, extract data, build and verify
make verify         # The permanent gate: byte identity with the original ROM
```

`make verify` compares the build against the original cartridge dump itself,
whose SHA-1 is pinned in `assets/manifest.json`. Any difference fails the build
and reports the first differing offset.

## Make Targets

### Basic Commands

```bash
make init           # Validate the ROM, extract data, build and verify
make build          # Assemble source -> fbuilt.bin (mismatch is a warning)
make verify         # Assemble and require byte identity (the gate)
make compare        # Compare an existing build without reassembling
make check-assets   # Validate data/ against assets/manifest.json
make split          # Re-extract binary data from the original ROM
make tools          # Build C decompressor tools
make unpack-data    # Decompress Nemesis/Enigma data
make clean          # Remove build artifacts (extracted data is kept)
make help           # Show all available targets
```

The toolchain folder is chosen from the host platform; override it with
`make PLATFORM=linux_x86_64`.

### Analysis Workflow

Automated procedure analysis using emulator screenshots:

```bash
make reference MOVIE=longplay   # Generate reference screenshots
make find-unanalyzed            # Find procedures needing analysis
make analyze MOVIE=longplay     # Run automated analysis
make report MOVIE=longplay      # Generate analysis report
```

### Documentation Workflow

Semi-automated procedure naming with Claude AI:

```bash
make set-movie MOVIE=longplay   # Set movie type for session
make prepare-batch COUNT=40     # Prepare batch of procedures
# -> read workflow/batch_procedures.txt
# -> write workflow/rename_batch.csv
make rename                     # Apply renames to source
make verify                     # Renaming must not move a single byte
```

### Utility Commands

```bash
make show-movie     # Display current movie setting
make stop           # Kill running Gens emulator instances
make build-gens     # Build modified Gens emulator (VS2022)
```

## How to Build

### Prerequisites

- Python 3.x
- Make (Git Bash / WSL on Windows)
- AS Macro Assembler (vendored in `bin/`, see `bin/README.md`)
- Original ROM: `Flicky (UE) [!].bin`, SHA-1 `83d8bbf0a9b38c42a0bf492d105cc3abe9644a96`

The ROM is never tracked by this repository and is not distributed with it.

### First Time Setup

```bash
# 1. Place original ROM in project root
#    Flicky (UE) [!].bin

# 2. Initialize project
make init
```

This will:
1. Validate the ROM against the SHA-1 recorded in `assets/manifest.json`
2. Extract binary data from the ROM into `data/*.bin` and check every segment
3. Build the ROM from source and require it to be byte-identical

### Regular Development

```bash
make verify     # Rebuild and require byte identity with the original ROM
```

## Known Issues

### Pointer Hardcoding at $10000

When adding padding before `Sys_GameEntryPoint` (address $10000), the game freezes in certain places. This is caused by hardcoded pointer offsets in `data/data_z80_part2.bin` that don't get recalculated when the ROM layout shifts.

The code in `Sound_LoadZ80Table` uses `suba.l #Sys_GameEntryPoint,a0` to convert offsets, but the offsets stored in the binary data file remain unchanged.

**Workaround**: Keep `Sys_GameEntryPoint` at exactly $10000.
